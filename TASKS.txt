Phase M0 — data spike (8 pts)
-----------------------------

[ ] S0.1  Fetch German data and write fixtures         (3 pts, needs nothing)

    Confirm whether kaikki.org publishes a German-only extract; record
    its existence and size. If only the English-edition dump (~2.3 GB
    compressed) is available, note that too.

    Write fixture files for the sample words covering:
      - one entry per word class (noun, verb, adjective, adverb, ...)
      - a compound:              Haustürschlüssel
      - a homograph:             Band (three entries)
      - a separable verb:        aufstehen
      - a reflexive verb:        sich freuen
      - a singular-only noun:    (pick during the spike)

    Fixtures are small, committed to the repo, kept out of src/main.
    Suggested location: ingest/src/test/resources/fixtures/kaikki/
    or (pre-ingest) a top-level fixtures/kaikki/ folder.


[ ] S0.2  Mapping report and go/no-go ADR              (5 pts, needs S0.1)

    Build a table: for each kaikki field, the brief's record field it
    fills, plus the fields that cannot be mapped. Decide the storage
    format for reflexive verbs (sich freuen etc). Propose a threshold
    for the ingestion gates (acceptable share of entries missing
    required fields).

    Write an ADR under docs/decisions/ using the template there.
    Decision: go, go-with-reduced-model, or no-go.
    If the content model must shrink, update docs/brief.md § Content
    model before anything else.


Phase M1 — foundations (5 pts backend-side)
-------------------------------------------

[ ] S1.4  Backend skeleton with CI and Dockerfile      (5 pts, needs S0.2)

    Multi-module Maven project: dictionary-core, ingest, api.
    api serves GET /api/v1/health and GET /api/v1/meta (meta returns
    the minimum app version, read from config).
    A tiny fixture dictionary.sqlite built from the S0.1 fixtures is
    opened read-only by the api.
    contracts/openapi.json is generated by the build.

    Workflow files exist and are green on every PR:
      .github/workflows/ci-backend.yml
        - job build: ./mvnw -q verify
        - job contract: regenerate OpenAPI and diff against
          contracts/openapi.json; fail if different
      .github/workflows/security.yml
        - gitleaks (secrets)
        - GitHub dependency review (new vulnerable deps)
        - actionlint (workflow lint)

    Non-root Dockerfile runs locally (docker run reaches /api/v1/health
    on a mapped port). Java and Spring Boot versions chosen and recorded
    in an ADR.


Phase M2 — add from dictionary (24 pts backend-side)
----------------------------------------------------

[ ] S2.1  Ingest nouns                                 (8 pts, needs S0.2, S1.4)

    Noun mapper fills: article, gender, plural, genitive, translations,
    examples. Golden-file tests cover Haus, the three Band entries and
    a singular-only noun.
    The ingest job builds dictionary.sqlite with an FTS5 index over
    forms and translations.
    Gates: golden-word test + row-count-vs-previous-run. A regression
    fails the run; the previous dictionary stays live.


[ ] S2.2  Ingest verbs and adjectives                  (8 pts, needs S2.1)

    Verb mapper fills: separable flag, auxiliary (haben/sein), Präteritum,
    Partizip II, and the reflexive form as decided in S0.2.
    Adjective mapper fills: comparative, superlative.
    Golden tests: laufen, aufstehen (separable), sich freuen (reflexive),
    schön.


[ ] S2.3  Lookup endpoint                              (8 pts, needs S2.2)

    POST /api/v1/lookup:
      - body validated: trim + NFC normalize + 1–64 chars,
        ^\p{L}[\p{L}-]{0,63}$; else 400 problem+json
      - body size cap 1 KB
      - case tolerant (Locale.ROOT, never SQLite NOCASE)
      - inflected form resolves to lemma with a note
      - homographs return several entries
      - unknown word returns the contract's not-found shape
    Rate limiting: per-IP; over limit → 429 problem+json.
    Logs record only pos, result (FOUND/AMBIGUOUS/NOT_FOUND) and
    latency. Never the typed text, never the IP.
    One test per case.


Phase M4 — remaining content (5 pts)
------------------------------------

[ ] S4.1  Ingest other word classes                    (5 pts, needs S2.3)

    Mappers for adverbs, pronouns, prepositions, conjunctions, numerals,
    interjections, particles. One golden word per class. The gates
    cover the new classes.


Phase M6 — release hardening (5 pts backend-side)
-------------------------------------------------

[ ] S6.3  Hosted deploy and monthly ingestion          (5 pts, needs S6.1)

    .github/workflows/deploy-backend.yml runs on a release tag.
    Hosting choice re-verified against free-tier reality and recorded
    in an ADR (default per brief: Render free tier; Cloud Run fallback).
    Monthly ingest workflow builds dictionary.sqlite from the fresh
    dump, runs the gates, deploys. A failed gate keeps the old
    dictionary live. Cold-start behaviour documented.

Process reminders
-----------------

- Before any change, run the change-ritual skill (.claude/skills/).
  It picks the right process by size and flags security triggers.
- For anything above a one-file trivial, write a plan in docs/plans/
  first using docs/plans/template.md.
- A PR into main needs 1 approving review (owner uses admin override
  on their own PRs: "Merge without approval" button; or relax
  protection later if friction bites).
- End every iteration with the learning-note skill — a four-bullet
  entry in docs/learning-log.md under today's date.
- Rituals and process files to revisit once development is flowing:
  tools/seed/ (dead code until a Project is wanted again),
  CODEOWNERS self-review enforcement (consider relaxing on solo
  branches), GitHub Project + issues.
